# CAMEO agent orchestration: audit and staged plan

**Audit date:** 2026-10-20  
**Scope:** existing CAMEO source/configuration and official upstream project material, including a shallow, isolated audit clone of `tanbiralam/claude-code` at `6f6f12b37f529488b10e53928dd5508bb93535c7`. No upstream dependencies, code, binaries, or installation scripts were installed or executed.

## Verified current architecture

- **Desktop shell/backend:** Tauri 2, Rust 2024. Commands are registered in `src-tauri/src/lib.rs`; the main window has a narrow capability allowlist in `src-tauri/capabilities/default.json`.
- **UI:** React 19 + TypeScript + Vite. Existing dock/workspace and task UI live in `src/App.tsx`, `src/pages/Tasks.tsx`, and `src/components/TaskExecutionWindow.tsx`.
- **Model integration:** `src/services/ai.ts` sends Tauri `chat` commands. Rust `src-tauri/src/commands/ai.rs` streams OpenAI-compatible requests to OpenRouter, NVIDIA NIM, Ollama, or a configured compatible provider. Provider API credentials are read by Rust from the OS credential store; there is no provider key in the frontend call contract.
- **Task execution:** a user creates a SQLite-persisted task, chooses one of five role profiles, requests a model-generated 3–6-step plan, approves it, and reviews bounded file proposals before per-file writes. A detected allowlisted check must pass before full completion. In addition, the existing task panel now offers three independent, read-only reviews (ATLAS, FORGE, SENTINEL) through the selected CAMEO model. This is a review fan-out, not an autonomous code-writing loop or general DAG planner.
- **Persistence:** Rust/Rusqlite owns `%LOCALAPPDATA%/CAMEO/cameo.db`, including tasks, proposals, preferences, `task_events`, and agent run records. Review state/results survive refresh/restart. SQLite transaction-guarded claiming fences attempts and enforces a two-running-worker cap across processes; only explicitly requested recovery marks runs older than 120 seconds interrupted, and user retry is bounded to two total attempts. This is not a resident background supervisor.
- **Command execution/security:** `devtools.rs` probes tools and exposes project inspection plus a narrow command allowlist. Model output is not directly executed. Review agents receive bounded secret-filtered source and no tool interface; CAMEO redacts credential-like task/source/output text, bounds output, applies request deadlines, and rejects stale completion after cancellation. File proposals remain path-checked, stale-preview checked, backed up, and per-file user-approved. Task deletion is refused while a review worker is running.
- **Build/tests:** npm scripts provide TypeScript typecheck, Vitest and Vite build; Rust uses Cargo tests/check. Initial inspection hit a local command broker spawn error; direct terminal execution subsequently succeeded, and current verification outcomes are recorded below.
- **Capability registry and project memory:** a separate audit of `affaan-m/ECC` (`ecc-universal` 2.2.3, MIT) added a bundled CAMEO capability registry, registry-gated planning guidance, and a project-memory SQLite store; see `ECC-INTEGRATION-PLAN.md` for the full classification and attribution.

## Direct audit: `tanbiralam/claude-code`

- **Actual contents:** shallow clone of the repository's `main` at commit `6f6f12b37f529488b10e53928dd5508bb93535c7` (merge commit, May 7, 2026); 2,015 tracked files, including 1,994 under `src/`, TypeScript/Bun CLI source, plugins, stubs, `README.md`, `package.json`, `bun.lock`, and `bunfig.toml`. Its own README titles it “Claude Code — Leaked Source (2026-03-31)” and states the source was leaked from an Anthropic npm source map.
- **Upstream relationship:** `origin` is `https://github.com/tanbiralam/claude-code.git`; clone is shallow and aligned with its `origin/main`. It is not Anthropic's official repo. `git ls-remote https://github.com/anthropics/claude-code.git HEAD` returned `a6e289a2e772a17b3614a9ef43303003de5cd887`; the fork/archive's shallow graph cannot establish full ancestry, and the repository self-identifies as leaked source, not a maintained official distribution.
- **README/package/install:** README describes a Bun v1.3+ runtime, Node.js v18+ for npm package install, Anthropic API key in `ANTHROPIC_API_KEY`, and `bun run start`; `package.json` has Bun start/dev/build/typecheck scripts. Dependencies include Anthropic SDKs, Claude Agent SDK, MCP, React/Ink, CLI, telemetry, native/platform-facing dependencies and local private-package stubs. It is an Anthropic-specific CLI harness, not a provider-neutral drop-in module for CAMEO's Tauri/Rust app.
- **Platforms:** README gives no authoritative support matrix. Source does contain Windows-specific code paths, but that does not establish supported Windows product packaging or security. Sandbox toggling explicitly documents macOS/Linux/WSL2 support only, excluding native Windows. The project is Bun-runtime-specific and depends on Bun `bun:bundle` flags, CLI/Ink, Node APIs, and native/private modules; not compatible with the current WebView/Rust command boundary as-is.
- **License and reuse:** no tracked `LICENSE`, `COPYING`, `NOTICE`, copyright grant, or third-party attribution file was found. README calls this leaked source, disclaims ownership and explicitly states original source belongs to Anthropic. Therefore do **not** copy or adapt source code, prompts, implementation, or bundled assets. This is a legal-risk finding, not a legal opinion.
- **Completeness and security:** README says internal `@ant/*` modules and other Anthropic packages are missing and replaced by no-op stubs. Verified stubs include browser/computer-use, sandbox-runtime and MCP bundle operations (e.g. the fake sandbox manager only resolves start/stop; computer-use tools return empty/null). README calls the source leaked and recommends setting `ANTHROPIC_API_KEY`; exposing that in CAMEO would violate CAMEO's OS credential-store boundary. Its source includes broad shell/file, network, MCP, plugin, updater, session, team and telemetry functionality that would require a separate security audit, sandboxing, permission review and egress controls. No upstream code/dependency/install command was run; no `node_modules` was created.
- **Features genuinely present in that tree:** source for CLI tools, hooks/permissions, plugin/skill systems, MCP/LSP, coordinator, task/session persistence and Windows branches is present. However, it is an incomplete leaked archive with stubbed private modules, not independently verified as runnable or safe; source presence is not equivalent to supported capability.
- **Integration decision:** no upstream source files or components were reused. CAMEO instead now supports a user-configurable review provider/model selection using its own typed provider adapter. The selection defaults to the primary model; each persisted review run records provider/model and retry/recovery use that original destination. Hosted-provider egress is disclosed in Settings and adjacent to the review action; Ollama remains local. This keeps CAMEO's provider keys in the Rust OS credential store and does not introduce CLI execution, extra privileges, copied prompts, or dependencies.
- **Rollback:** clear the separate review-model selection with **Use primary for reviews**; no schema migration, dependency, external executable, source copy, or alteration to the primary task/approval workflow is required.

### Upstream verification limitations

Official upstream READMEs, available license statements, GitHub advisory/release pages, DeepSeek Harness `SAFETY.md`, and Looper's official installation guide were checked. Upstream findings: DeepSeek Harness calls itself experimental/unaudited and warns sandbox/approval controls are not a security guarantee; Orca has no GitHub releases despite README availability claims; Looper's current packaged target excludes Windows and its binaries are unsigned; Herdr restores supported session state but not original processes after reboot. No published advisory was displayed for DeepSeek Harness, Orca, Claudex Loop, Looper or Herdr. These observations are not a security audit. The DeepSeek docs site timed out, and Herdr's `LICENSE` blob fetch was unavailable; its stated license comes from its repository README. No installation scripts or binaries were run.

## Integration decision

CAMEO remains the coordinator and owner of its task/event database, provider credentials, per-file approval and verification. Do not combine Orca, Looper and Herdr as competing schedulers. Keep external engines behind a narrow adapter that receives bounded task context, returns progress/results and supports cancellation; its adapter must not receive secrets or implicit merge/deploy authority. Cross-model review is opt-in and must disclose which context leaves the device.

## Implemented stages and remaining gated work

1. **Audit + plan (complete).** Source architecture and upstream fit recorded above; no unverified software installed or run.
2. **CAMEO-owned read-only review adapter (implemented in this slice).** Uses existing selected provider/model. ATLAS/FORGE/SENTINEL run independently with a global two-worker cap, 120-second request deadline, two attempts maximum, user retry, cancellation, and SQLite-persisted run status/result/events. The task panel discloses that descriptions and project files are sent to the selected provider (Ollama remains local). No command or file-write API is passed to reviewers. Acceptance is covered by orchestration and UI tests for provider routing, concurrency, cancellation/late-result fencing, retry limit, result display, egress notice, and no file proposal/write side effect. Rust unit tests verify the timeout is in milliseconds and bounded. The original single-agent approval flow remains.
3. **Safe persistence/recovery (partially implemented).** SQLite claim transaction enforces worker cap and attempt fencing across app instances; old running attempts are not changed on startup. Explicit per-task recovery marks only 120-second-expired workers interrupted and emits an event; failed/cancelled workers can be retried. Remaining acceptance: Rust command-level fixture tests for restart/recovery idempotence and concurrent claim contention; no persistent background supervisor is included.
4. **Isolated autonomous coding workers (deferred).** Orca is an evaluated candidate, but no safe pinned Windows artifact exists at the time checked. No agent CLI, sandbox or worktree automation is integrated. Any future engine must use isolated worktrees plus OS sandboxing, budget/time controls and CAMEO review/per-file approvals.
5. **Independent review model (partially implemented).** Settings can select a review provider/model separately from the primary model, with primary-model fallback. Each review record pins its provider/model so retries and recovery keep the same egress destination. This enables provider/model separation when the user chooses it, but agents are still advisory prompts in one CAMEO runtime rather than independent coding products; the Run/Retry action is the visible egress gate and there is no additional consent dialog. CAMEO exposes task/source egress in Settings and at the task review action.
6. **GitHub issue-to-PR workflows (deferred).** Looper is not integrated; no GitHub credentials, issue authority, push, PR, merge or deployment operation was added. Human approval and least-privilege auth need a dedicated stage.
7. **Herdr (deferred).** Exact repo confirmed but not embedded/installed; terminal management is outside current task/UI architecture.

## Rollback

The review addition is isolated behind the existing task-panel action; leave it unused to retain the prior workflow. It adds review runs/events without replacing task/proposal data. It does not delete files, binaries, credentials or worktrees. Keep the original provider, task, approval and proposal path intact; do not remove user databases or perform external installations/authorizations without a separate approval.
